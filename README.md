## 日本VPS速度测试：到底该测哪些指标

很多人测VPS速度就跑一个 speedtest 截个图完事，这跟体检只量个体温一样——能发现发烧，但发现不了别的毛病。一套像样的日本VPS速度测试，至少要覆盖下面几个维度。

**延迟测试**。这是最基本的。用 ping 测三网（电信、联通、移动）到日本节点的 RTT（往返时延）。日本到中国大陆的物理距离决定了延迟底线——通常电信和联通在 40-70ms 之间算正常，移动可能稍高一些。如果某条线路延迟低于 50ms，那基本可以判断走的是优化线路而非普通公网。

**带宽测速**。别只测一个节点，至少从国内不同地区、不同运营商的测速节点连过去跑一下。重点关注两个数：下行带宽和上行带宽。很多商家标 1Gbps 端口，但你实际能跑到多少，取决于线路质量和晚高峰拥塞程度。

**回程路由追踪**。这是最容易被忽略、但也最能说明问题的一项。用 traceroute 或 mtr 看从日本VPS回到国内走的什么路。如果回程经过 CN2 GIA、联通 AS9929、移动 CMIN2 这些精品线路，那速度和稳定性就有保障；如果走的是普通 163 线路或者绕路去了美国再回来，那就等着晚高峰掉速吧。

**晚高峰专项测试**。晚上 8 点到 11 点是国内互联网出口最拥堵的时段。一个VPS白天测飞快、晚高峰拉胯，对你来说就等于半残。所以测试一定要覆盖晚高峰时段，至少连续测三天。

## 日本VPS速度测试实操：手把手教你测

说了这么多理论，给你一套可以直接照着做的测试流程。

**第一步：延迟测试**

从国内不同运营商的网络环境 ping 你的日本VPS IP。如果你自己没有多运营商环境，可以用国内的在线 ping 测试工具（比如站长工具的 ping 检测），选择电信、联通、移动各几个节点来测。

记录三个数据：平均延迟、最小延迟、抖动（jitter）。抖动大的话说明线路不稳定，即使平均延迟低也不行。

**第二步：带宽测速**

在你的日本VPS上安装 speedtest-cli（Linux 命令行版本），然后选择国内不同地区的测速节点跑测试。重点测北京、上海、广州三个方向，覆盖南北不同地理位置。

同时你也可以反过来测——从国内的测速节点连到你的日本VPS上跑下载测速，这样测的是"国内到日本"的下行带宽。

**第三步：回程路由追踪**

在VPS上安装 mtr（My TracerRoute），然后 mtr 你的国内 IP 或者国内某个公共 IP（比如 114.114.114.114）。看回程经过的每一跳，重点关注：

- 是否经过 CN2 骨干网（AS4809 的 IP 段）
- 是否经过联通 AS9929 节点
- 是否经过移动 CMIN2 节点
- 有没有绕路（比如先去美国再回国）

**第四步：晚高峰专项**

在晚上 8 点到 11 点之间，重复上面三步测试。连续测三天，取平均值。如果晚高峰延迟比白天高出 50% 以上，或者丢包率超过 5%，那这条线路的晚高峰表现就不及格。

**第五步：流媒体解锁测试**

如果你买日本VPS是为了看 Netflix、YouTube Premium、Disney+ 这些流媒体，那还要测一下 IP 是否被解锁。可以用现成的流媒体检测脚本（GitHub 上一搜一堆），一键检测你的 IP 对各大流媒体平台的解锁状态。
